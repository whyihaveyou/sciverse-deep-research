# orchestration.md — 强编排形态：子问题并行 + 无损合并 + 反思补搜

> 目标：根治"调研不充分"。借鉴 open_deep_research（LangGraph supervisor/研究员，
> github.com/langchain-ai/open_deep_research）、gpt-researcher（planner 拆子问题 +
> 20 源聚合）、dzhng/deep-research（critique→re-search→update 递归）。
> 本 skill 的优势（引用台账防幻觉、compile 铸号、check_report 门禁）保持不变并作为
> 编排的下游承接地。

## 何时启用

研究简报冻结后，若研究问题 RQ 具有**可拆分的子问题结构**（绝大多数多子主题综述都如此），
进入编排模式；单点小问题（一个 RQ、单一机制）退化为普通顺序模式。判据：能否把 RQ
拆成 ≥2 个可独立回答、相互不重叠的子问题。

## 编排四阶段（替换顺序模式的"多视角检索"，下游编号冻结/综合/编译不变）

### 阶段 O0：拆解子问题集（编排入口）

把研究简报的 RQ 拆成 **MECE 子问题集** `S1..Sn`（互斥且完备）。每个子问题：

- 一句话可独立回答（不依赖其他子问题结论）；
- 有独立的关键词族与检索策略（见 search-strategy.md 的关键词模式）；
- 隶属一个检索视角（主流/批评/相邻/方法论/应用）；
- 落到现有 taxonomy 的某一分支（供合并时归位）。

子问题拆解示例（"空间算力物理可行性"）：
- S1 技术路线（轨道边缘/遥感云 AI/太阳能 DC）
- S2 热管理物理瓶颈
- S3 辐射与可靠性
- S4 材料与能源解耦路径

**可编辑检索计划**：子问题集确定后，生成 `.workflow/search_plan.md`：

```markdown
# 检索计划
- 研究简报 RQ：...
- 子问题列表：S1...Sn（每句一句话 + 所属视角）
- 每个子问题的关键词族（≥2 组）
- 信息源：sciverse / arXiv / OpenAlex / 网页核验
- 时效窗口：按 search-strategy.md 的时效精度分级为每个子问题选档
- 检索轮次预算：每子方向 ≤3 轮（初始 + 2 轮补搜）
- 预期产物：每子问题一份 `subproblems/Si.md`
```

该计划**人机可编辑**。用户或执行者在 Step 0 / O0 阶段修改后，后续检索必须按修改后的计划执行；若未修改，则按自动生成的计划执行。这是把 SciMaster "人在环中调整任务逻辑" 的做法落到本地 skill 的轻量实现。

### 阶段 O1：子问题并行深挖

**每个子问题分派一个独立 sub-agent 深挖**（编排 agent 用并行委托机制/spawn、
batch，如 Hermes 的 delegate_task batch）。每个 sub-agent 拿到：

1. 该子问题的研究简报切片（独立 RQ + 关键词 + 视角）；
2. 统一的产物模板（见下"子问题产物"）；
3. 明确边界：只检索本子问题，不越界综合。

每个 sub-agent 内部按阶段一的检索步骤执行：多视角关键词 → 结构化/语义/滚雪球 →
存在性核验 → 产出**经核验的子问题文献清单**（每篇一句话发现 + unique_id + 主题归位）。

**子问题产物模板**（写入 `.workflow/subproblems/Si.md`）：
```
# 子问题 Si：[一句话]
## 检索记录（query × 来源 × 命中数）
## 候选清单（每篇：key/title/作者/年/一句发现/unique_id/拟分配主题）
## 本子问题的已知盲区（搜不到的方向，标"可能是空白或关键词不对"）
## 建议纳入综述的核心文献（≥3 篇）
```

> 并行是充分度的关键：单 agent 顺序跑 5 个视角，上下文与精力会被前几个视角耗尽，
> 后面的视角必然浅。并行让每个子问题都有完整上下文深度检索。

### 阶段 O2：无损合并 + 交叉去重

编排 agent 收集所有子问题产物，**逐字保留**地合并为 `evidence_merge.md`（见
research-depth.md 第 1 条"无损证据合并稿"）：

- 每子问题一节，映射 S_i → 既有 taxonomy 分支；
- 同质陈述跨子问题合并（"两源都报道 X"），但仍保留每篇源头；
- 交叉去重：同篇论文在多个子问题出现 → 保留一篇、在归属分支注明"亦涉 S_j"；
- 末尾列**全部**来源与检索式，作为检索收敛凭证。

### 阶段 O3：反思门禁 + 补搜循环

合并后做 Coverage/Insight 门禁自查（与 quality-gates 一致），但改为**显式多轮**：

- 每子问题是否 ≥3 篇核心文献？缺 → 回调该子问题补搜（不重跑全量）；
- 每个子问题是否执行过 `references/search-strategy.md` 的"裁判型文献定向检索"？未执行 → 补质疑式检索；
- 合并后的每个 taxonomy 分支是否至少含 1 条 L3/L4 洞见候选？缺 → 回调对应子问题补挖边界/机制文献；
- 有没有子方向所有视角都没覆盖？→ 补盲区检索；
- 时效探针：每个子问题一轮近 6-12 个月限定检索，记录命中；
- **反思问题**：这份合并稿里，"缺哪篇 / 哪句无出处 / 哪里矛盾"——回答不了的
  转化为证据缺口，写到开放问题，不许删。
- **意图演化日志**：每轮补搜后必须追加 `.workflow/intent_evolution_log.md` 一条记录：
  - `round`、针对的子问题、本轮 evidence、发现的缺口、`updated_intent`、`updated_checklist`、是否继续补搜。
  - 日志是 O3 多轮收敛的审计轨迹，也是后续综合阶段判断"为什么漏掉某方向"的依据。
- 收敛判据：补搜一轮零新增且各子方向 ≥3 篇 → 进入编号冻结。

### 阶段 O4：移交下游

把合并稿（已含 taxonomy 归位）作为**阶段二综合的输入**，进入既有流程：
编号冻结（铸台账）→ 键值草稿 → compile → check_report。合并稿淘汰：综合阶段以
合并稿为证据地基，不重新检索。

**进入综合阶段时的特殊路由**：若某 taxonomy 分支在初稿后仍无法产出 L3/L4 级洞见，
启用 `references/synthesis-framework.md` 的 **Mini scattered-and-stacked 深度合成**：
对该分支生成 2-3 个候选解读 → Critic 批判 → Rewriter 综合 → Selector 定稿。
该流程 borrowed from X-Master 的 Solver/Critic/Rewriter/Selector，用于在证据不足或观点分歧时
把洞见深度"赚到"，而不是原样放低标准交付。

## 子问题执行纪律（防止步骤性质混淆）

每个子问题 agent 内部的任务必须显式标 `step_type`，与 DeerFlow 1.x Planner 的 step 类型一致：

- `research`：必须用外部工具检索/读取信息（对应 `need_search: true`）。**禁止**在本步做数学计算、禁止写代码处理数据、禁止做跨文献综合——只做信息收集。
- `analysis`：只做推理、比较、综合、裁决，**不**调用检索工具、**不**写代码。
- `processing`：只调用脚本/Python 做确定性计算/数据转换（如 `citation_ledger.py`、自定义统计）。**不**做价值判断、**不**解释科学含义——输出交给 analysis 步使用。

混淆是常见失败模式：在检索步里顺手"分析一下"会污染上下文、在分析步里"再去搜一下"会破坏综合节奏、在 processing 步里"解释结果"会让脚本输出不可复现。主 agent 派发子任务时必须写清 step_type，子 agent 返回时标题里带类型标签。

## 子问题产物：并行元数据抽取（batching 规则）

子问题 agent 拿到候选文献后，**不要自己逐篇读完全部摘要再写**。按 DeerFlow 2.0 systematic-literature-review 的 batching 模式抽取元数据：

| 文献数 | 批次数（每批 ~5 篇） | 轮次 | 每轮 subagent 数 |
|---|---|---|---|
| 1–5 | 1 | 1 | 1 |
| 6–10 | 2 | 1 | 2 |
| 11–15 | 3 | 1 | 3 |
| 16–20 | 4 | 2 | 3 + 1 |
| 21–25 | 5 | 2 | 3 + 2 |
| 26–30 | 6 | 2 | 3 + 3 |

**约束**：
- 每批最多 ~5 篇，保证 subagent 上下文聚焦；
- 每轮最多 3 个 subagent 并行，避免宿主并发上限导致静默丢弃；
- subagent 只读文本、返回固定字段 JSON，不联网、不重新检索。

**固定抽取字段**（与 synthesis-framework.md 的引文抽取对齐）：

```json
{
  "arxiv_id_or_unique_id": "...",
  "title": "...",
  "authors": "...",
  "year": "...",
  "research_question": "1 句话",
  "methodology": "1-2 句话",
  "key_findings": ["3-5 条 bullet"],
  "limitations": "1-2 句话",
  "relation_to_others": "支持/挑战/扩展了哪类工作",
  "evidence_chunks": [
    {"doc_id": "...", "offset": 0, "quote": "支持核心发现的一句原文"}
  ]
}
```

主 agent 收集全部 JSON 后，再进入主题聚类与合并稿写作。

## 检索轮次预算与最佳证据兜底

编排模式不是无限循环。为补搜设置硬预算：

- **默认预算**：每个子方向最多 3 轮补搜（初始检索 + 2 轮补搜）。
- **终止条件**：任一子方向达到预算上限仍未收敛 → 用当前最佳证据继续，但必须在该子方向的 `Si.md` 中显式标注「检索预算耗尽，以下结论基于当前最佳证据，可能存在遗漏」。
- **全局预算**：整个阶段 O1-O3 的迭代不宜超过 5 轮；超过则强制进入 O4，把未解缺口写入「开放问题」。

预算耗尽不是失败，而是诚实的边界声明。禁止为追求"全绿"而无限补搜、也禁止把未解缺口悄悄删掉。

## 封装的承接

- 并行去重、证据合并、门禁计数等**确定性部分**可由编排 agent 用脚本做辅助；
- 引用台账（citation_ledger.py）、compile、check_report **不变**——它们是本 skill
  的强项，编排只改变"证据怎么来"，不改变"证据怎么铸号、怎么验收"。

## 与普通模式的关系

- 编排模式：≥2 子问题、并行、无损合并、反思多轮——用于大型综述；
- 顺序模式：单点小问题，保持现有阶段一五步——用于快速回答。
- 二者最终都收敛到同一套编号冻结/综合/编译门禁，保证交付标准一致。
